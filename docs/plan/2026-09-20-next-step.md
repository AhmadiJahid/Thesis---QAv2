Every run: committed code + committed config + seed 42, log row written **before** launch,

(the one exp-015 used). Only the model changes between arms — Ahmmad's "one change, and test".

G1a first for three reasons. It needs no new code, so it validates the 4-bit + unguided + pinned-600
recipe on the machine before the Qwen folders land. It is the Mistral point of the family
contrast, so the block cannot report without it. And because exp-015 is the *same* arm at
`quantization: none`, G1a versus exp-015 is a free same-eval-set reading of what 4-bit costs
Mistral — the third factor ADR 0031's amendment names. That reading is a by-product, not a new
arm, and it is reported as such.

**G2's comparator.** exp-008 `full_train` was trained and evaluated at `quantization: none`. The
`pool_2000` adapter should follow exp-008's precision so the pool-only vs full-train contrast
moves one factor (training data). This means G2 is on a different precision axis from G1; the
write-up states that rather than papering over it. If Jahid prefers one axis for the whole block,
that is a §4 decision, not the runner's.

**Stop condition (phase plan §6, flagged for Jahid's agreement, not adopted).** If G1a, G1b and
G1c come back near-identical on the report card, stop before G3 and investigate, because that
would reopen Ahmmad's "many changes, no effect" concern at the model level. exp-019's finding
that the harness does discriminate makes this less likely to fire, not impossible.
