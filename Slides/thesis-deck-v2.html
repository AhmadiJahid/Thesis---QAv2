Motivation

Most questions worth asking are not one lookup

A knowledge base holds facts as single edges. A question like the one on the right touches three of them, and no single lookup answers it.

Systems that answer it well do so by planning first — turning one hard question into a short sequence of easy ones.

“What languages are spoken in films that share a director with The Matrix?”
The plan is the object of study here — not the final answer.
Motivation

The plan is three ordered steps, and each needs the last

1Who directed The Matrix?
2Which other films did [#1] direct?
3What languages are spoken in [#2]?
The [#k] placeholders are what make this a plan rather than three unrelated questions. They also make it machine-checkable: a step that references a nonexistent earlier step is detectably broken.
Ordered · atomic · explicitly linked
Problem definition

What goes in, what must come out

Input
Q   a multi-hop questionnatural language
D   a domainthe knowledge source
Output
Q′ = ⟨q₁ … qn⟩ordered sub-questions

Each qi is answerable by a single lookup in D, and may reference [#j] for j < i.

n is not given at inference time — the model must decide the length too.
Challenges

Three ways a decomposition goes wrong

The three failures are independent, and one accuracy number hides all of them.

Wrong lengthThe model has to infer how many steps the question needs. Too few drop a hop; too many invent one.
Broken chainA later step has to consume an earlier answer. Steps that restate the original question look fine and compose to nothing.
Invented entitiesThe model names people and films that are not in the knowledge source, so the plan cannot execute.
This is why the evaluation separates length, order and content rather than reporting a single score.
Each failure mode maps to a metric family later in this deck.
Methodology · overview

Everything that moves sits in how the prompt is built

Stage B is held constant on purpose. If the decomposer and its decoding never change, then any difference between runs is attributable to prompt construction alone.
Each stage-A component gets its own slide next.
Methodology · component 1

Masking makes similarity a statement about shape

Retrieval over raw text finds examples that share names. Shared names say nothing about how many hops a question needs.

rawentities intact
which films did Christina Ricci star in after The Addams Family in 1991
uniformone shared token
which films did [MASK] star in after [MASK] in [MASK]
typedtype label kept
which films did [PERSON] star in after [MOVIE] in [YEAR]
The pool is masked once in advance, never at query time — dynamic masking corrupts titles that collide with common words.
Methodology · component 2

The few-shot pool is a sample, and how it is drawn is a choice

Every prompt draws its examples from one pool. The pool is built once, before any question is asked — and three strategies build it differently.

ImbalancedDraws uniformly. The pool inherits whatever mix the corpus already has.
BalancedFills an equal quota from each hop bucket, so no hop count dominates.
Clusteredk-means over the pool, one example per centroid — covers the spread rather than the frequency.
MuSiQue is dominated by two-hop questions. An imbalanced pool inherits that skew, so the harder multi-hop examples are the scarcest thing in the prompt.

Research questions

Now that the method is on the table, these are the questions it asks

1 Does how the few-shot examples are chosen — masking, pool, retrieval, rerank — determine whether a mid-sized model can decompose at all?
2 Does knowing the hop count in advance help, and is the answer the same across models?
3 Does fine-tuning beat prompting — and does it still hold at a depth it never saw in training?
4 Do better plans produce better answers end to end?
Every claim that follows is paired to one of these four.

Setup · metrics

One number cannot catch three different failures

Is the length right

Hop-count EM

Predicted step count equals gold. Reported with under- and over-decomposition as a pair, never summed — too few steps is worse than too many.

Is the chain intact

Chain validity

Do the [#k] links resolve into one connected chain with no orphans? Junk scores zero.

Is the content right

SARI · GED · Break EM

N-gram overlap against gold, graph edit distance between step graphs, and the strict whole-plan match.

Why not one blended score: a content-perfect but reversed plan scores at the top of the table on both GED and SARI. Only the strict match and the ordering terms catch it. Six unblended terms are reported; a report quoting fewer is not reporting it.

Setup · metrics

Ordered step accuracy, when the two lengths disagree

Steps are compared position against position — there is no alignment step. The denominator is the longer of the two:

matches at the same index
────────────────────
max(npred, ngold)
Predicted 3, gold 2
step 1 matches✓
step 2 matches✓
step 3 — no gold to comparecounted against
Score2 / 3
A surplus step is never compared, but it still enlarges the denominator — so it costs the same as a wrong one. The metric cannot reach 1.0 unless the lengths match, which is what makes it an ordering and length measure at once. A fully reversed 3-step plan scores 1/3 while step F1 scores 1.0.
Exact string equality after normalisation — no partial credit per step
Setup · metrics

The score that used to rank these runs has been retired

Composite score — a hand-weighted blend:
0.4·step F1 + 0.3·ordered + 0.2·ref validity + 0.1·count error

Its 0.2-weight reference-validity term was decided by a bracket-format mismatch: the scorer looked for [#k], the evaluation data writes #k. The term was effectively settled by 2 of 600 items.

±0.2 how far the composite swung across nine pairs on which graph edit distance moved a stable +0.01 to +0.02 in one direction
It stays computed and stamped legacy so older tables remain reproducible — and it ranks nothing from here on.

Setup · statistics

The metric's type chooses the test

Continuous scores

Paired bootstrap

10,000 resamples, 95% confidence intervals.

Binary outcomes

Exact McNemar

On the discordant pairs only.

Agreement check

Paired t-test

Run alongside, never instead.

Everything is paired. Both arms of every comparison answer the same pinned 600 questions, so per-question difficulty cancels and the test sees only the difference between methods. Underpowered cells are reported as underpowered; noise-scale effects are named as noise.

Part four

Where this goes next

What the evidence does not yet cover, and the experiment designed to cover it.

Next · the gap in the evidence

Almost every result here is one model's result

Of every MuSiQue arm run, all but one use Mistral-7B. The single Qwen arm disagrees with the Mistral finding it is usually quoted beside.

So “hop guidance is worth little” and “fine-tuning beats prompting” are currently claims about the same one model — and the model that disagrees with the first was never brought into the second.
The experiment

Hold everything, vary one thing

Same 2,000-example imbalanced pool, same pinned 600, same unguided condition, same decoding.

Mistral-7B Qwen2.5-7B Qwen2.5-14B

Mistral vs Qwen-7B isolates the family. Qwen-7B vs Qwen-14B isolates the size. Each contrast moves exactly one factor.

Qwen3.5-9B is deliberately not the size rung — it differs from Qwen2.5-7B in generation as well as parameter count, so it would confound the two. Bringing it into the fine-tuning claim is a separate arm, and a cheap one.

Four more things, in order

1 A fine-tune trained on the pool alone — 2,000 examples, not the full 19,938 — to isolate what the pool itself is worth.
2 A fixed 45-question anchor set, 15 per hop, inspected by hand in every experiment from here on. The same questions every time.
3 Few-shot example ordering — currently highest-similarity-first, never varied. Reversed, and least-complex-first.
4 Whether the null generalises — pool construction is now measured as a genuine null, but masking, retriever and pool size have not had the same stage-by-stage check.

Honest boundaries

What this evidence does not support

Single-model scope

The hop-guidance finding is Mistral-specific; Qwen3.5-9B behaves differently.

No human judgement

Exact match against one gold plan penalises valid alternatives. No human validity study has been run.

Typed vs uniform untested

The gap sits inside plausible run-to-run variance and carries no significance test.

MetaQA end-to-end blocked

The integrated graph run depends on an external system not yet available.

Pool evidence is one trial

One draw per strategy mixes the strategy's effect with the noise of that draw.

No LLM judge, by design

Early scoring used one; it is not ground truth and those figures are not evidence here.

Anything not backed by a run artifact is reported as unmeasured.
